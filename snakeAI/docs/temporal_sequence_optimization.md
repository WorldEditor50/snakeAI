# 时序信用分配优化记录

覆盖 DRPG（LSTM 策略梯度）、MPG（Mamba 策略梯度）与 `LSTM` 本身在
**时序依赖任务**上的缺陷、修法与实测。相关文档：`drpg_analysis.md`、
`lstm_gradient_analysis.md`、`mamba_design.md`、`ssm_design.md`。

> 方法论提醒：本文所有结论都基于 **≥20~30 组的配对试验**。
> 早先基于 6 次试验得出的结论是错的，见 §5。

---

## 1. 任务与判据

2 步时序任务（temporal credit assignment）：

```
s0 = [1,0,0] (pattern A) 或 [0,0,1] (pattern B)   ← 只有这一步能区分 pattern
s1 = [0,1,0]                                       ← 与 pattern 无关
pattern A → s1 处最优动作 0
pattern B → s1 处最优动作 1
奖励只在 s1 给出（对=1，错=0），s0 的动作不影响奖励
```

**必须靠循环状态把 s0 的信息带到 s1**，否则在 s1 处最优只能固定成一个动作
→ 准确率恰好 50%。所以"准确率 50%"就是"循环通路完全无效"的指纹。

判据：每回合 `resetState()`，最终在**全新的单条 2 步序列**上用 argmax 评估
（不因为训练方式而放水）。

---

## 2. 缺陷与修法

### 2.1 `action()` 回退循环状态 ✅（最关键的一条）

```cpp
// DRPG::action 原实现
lstm->h = h;    // h/c 是"上次训练前保存的值"
lstm->c = c;
return policyNet.forward(state, true);
```

`MPG::action` 同理恢复 `mamba->h = mamba_h`。

**后果**：连续两次 `action()` 之间循环状态**无法传递**——每次调用都被重置回
同一个快照。于是 2 步任务退化成"把 s1 映射到固定动作"，**准确率精确落在 50%**。

**修法**：删除回退。不需要恢复，因为 `reinforce`/`reinforce1` 都会把轨迹从
reset 状态重放一遍（权重未变），结束时活跃状态恰好等于"轨迹结束后的状态"，
那正是推断应当继续的状态。

### 2.2 `MPG::gumbelMax` / `noiseAction` / `eGreedyAction` 回退状态 ✅

`action()` 修好了，但同类的三处**漏了**——都在开头做 `mamba->h = mamba_h;`。
后果比 2.1 更隐蔽：

1. 一次 rollout 内 Mamba 状态不能逐步传递 → **采样出的动作不含任何时序信息**；
2. `reinforce1` 从 `mamba->reset()` 重放求梯度 → **被微分的分布 ≠ 生成数据的分布**，
   梯度有偏。

**修法**：三处全部删除。`reinforce`/`reinforce1` **末尾**那次恢复是合法的
（保存 → reset → 重放 → 恢复，为了重放后继续推断），保留。

### 2.3 rollout 从不重置循环状态 ✅

`reinforce`/`reinforce1` 从 **reset** 状态重放轨迹做 BPTT，但
`agent.cpp` 的 rollout 从不重置——**重放时的前向传播与产生数据的策略不是同一个**。

**修法**：`drpgAction`/`mpgAction` 的 rollout 开头加 `resetState()`
（`DRPG::resetState` 清 `h/c` 与 `lstm->h/c`；`MPG::resetState` 清 `mamba_h` 与 `mamba->h`）。

**实测**（2000 回合）：

| 每回合 reset | DRPG | MPG |
|---|---|---|
| 否 | ~50% | ~50% |
| **是** | **100%** | **86.8%** |

并且**增加回合数救不了失败的 run**（2000 / 5000 / 10000 全部卡在 ~50%）
→ 是**初始化依赖的双峰**，不是收敛慢。

### 2.4 Mamba 的 `C` 与 `W_in/b_in` 初始化过小 ✅

从 `U(-0.1, 0.1)` 提高到 `U(-1, 1)`。这是本轮唯一一条纯初始化改动，效果显著：

| | 改动前 | 改动后 |
|---|---|---|
| 上下文效应 `max\|y(after A) − y(after B)\|` | **0.01** | **0.27 – 0.68** |

原初始化下 Mamba 对历史输入几乎**没有响应**。

### 2.5 Mamba 反向传播的两处 ✅

- `delta_h[i] = delta_.h[i]` 改为 `+=`（原来是覆盖赋值，来自后续时刻的梯度被丢掉）；
- softplus 的导数改用标准形式 `sigmoid(x)`（原实现是另一条曲线）。

### 2.6 `LSTM` 的三处 ✅

- `outputError` 按 `hiddenDim` 分配，实际应 `outputDim`；
- 细胞状态导数写成 `Tanh::df(states[t].c[i])`，应为 `Tanh::df(Tanh::f(c))`
  （`c` 是**未激活**的细胞状态，`Tanh::df` 接受的是**激活后**的值）；
- `read()` 里 `us`/`bo` 读错位置 → 保存/加载往返不一致。

**BPTT 本身是正确的**：`backwardAtTime` 里的递推完整
（`δh_t = Wᵀδy_t + Σ_gate Uᵀδgate_{t+1}`、`δc_t = δh_t⊙o⊙tanh'(c_t) + δc_{t+1}⊙f_{t+1}`
等），§7 的 adding problem 达到 eval MSE ~0.003 也反证了这一点。

## 3. 训练过程的优化：一次更新内重复同一序列

单条 2 步轨迹的梯度噪声极大：反向递推得 `G_1 = r`、`G_0 = γr`，
取均值基线后 advantage 只有 `±0.05r`；而**第 0 步的动作与奖励无关**，
却贡献同量级的噪声。结果是训练呈现**双峰**——要么在 ~400 回合内锁定依赖，
要么永远学不会。

**修法**：一次更新内重复同一 pattern 的 2 步序列 4 次（等价于 mini-batch REINFORCE）。

这不是"给测试放水"：真实 agent 的 rollout 本来就是 **16 / 32 / 128 步**，
2 步的 batch 才是原测试里不现实的地方。评估仍然只用**一条全新的 2 步序列**。

### 30 组配对试验（同种子 ⇒ 同初始化）✅

2000 回合、200 样本确定性评估、成功 = 最终准确率 > 90%：

| 算法 | reps=1 | reps=4 | reps=8 |
|---|---|---|---|
| DRPG (LSTM) | 24/30 (80%) | **28/30 (93%)** | 29/30 (97%) |
| MPG (Mamba) | **14/30 (47%)** | **29/30 (97%)** | **30/30 (100%)** |

配对差异（reps=4 vs reps=1）：DRPG 5 修好 / 1 弄坏；MPG **16 修好 / 1 弄坏**
（McNemar 精确 p ≈ 0.0003）。

**结论**：对 MPG 是决定性改善（47% → 97%），对 DRPG 是温和改善（80% → 93%）。
DRPG 残留的 7% 是**初始化依赖**：失败的 run 最终准确率恰好 ~50%
（策略忽略 s0），且加长训练无效。

## 4. 测试设计自身的缺陷（已修）

### 4.1 首次评估太晚 → "学得快"被判为失败 ✅

原来首次评估在第 400 回合之后，于是已经收敛到 100% 的策略**没有提升空间**，
`trend` 检查（要求 final > first）把它判成失败。

**修法**：ep 0 先测**未训练基线**，`trend` 与它比较。

### 4.2 未训练基线可能是"幸运的 100%" ✅

贪心评估下，随机初始化的 Mamba 有时**已经**对两个 pattern 都输出正确动作
（实测 30 次里有 5 次），这时这一 run 是**空洞**的：没有东西可学，
而"必须严格提升"的判据把它报成失败。

**修法**：`trend` 放宽为"有提升 **或** 已到顶（≥0.99）"。
这不影响回归检测——`reinforce1` 若损坏，策略会停在 ~50%，被 `pass` 判据挡住。

### 4.3 `test_pg` Test 4 的训练/评估条件不一致 ✅

评估在**每次决策前**都 `resetState()`，测的是 `(s1, h=0)`——
而 LSTM 训练时**从未见过**这个条件（轨迹总是把 `h` 从前一个 `s0` 带过来）。
网络于是把 s1 的决策编码成"相对于那段历史"的，探针条件不匹配。

在同一份训练好的权重上做**完美配对**对比：

| 探针 | 通过 |
|---|---|
| 旧（每步 reset） | 18/30 |
| 与训练一致（先 s0 再 s1） | **25/30** |

**7 项修好、0 项弄坏**（McNemar 精确 p ≈ 0.016）。

## 5. ⚠️ 我自己的错误：6 次试验得出的结论

我最初用 **6 次独立试验**测量 reps 的效果，得到 `reps=1 → 5/6`、`reps=4 → 6/6`，
就在代码注释里写了"**完全消除双峰**"。

**6 次试验根本无法区分 83% 与 100%。** 改用 30 组配对试验后，真实数字是
24/30 与 28/30（DRPG）——提升确实存在，但远没到"消除"。
注释里已经更正，并明确写出"早先的 6 次试验样本太小，结论已作废"。

**教训**：本任务的结果是**双峰且由初始化主导**的，
所以试验必须①配对（同种子）②样本足够（≥30）。
非配对的、小样本的对比在这种任务上会给出错误结论。

## 6. 复现方法

```powershell
# 时序测试（各 20 次独立运行）
build\verify\test_pg.exe      # Test 3 = DRPG 时序
build\verify\test_mpg.exe     # Test 3 = MPG  时序

# 单元级
build\verify\test_lstm.exe
build\verify\test_mamba.exe
```

测量 reps 效果需要配对试验脚手架（本轮用后已删除）；复现方法：
对每个 trial 取同一个种子 `seed`，分别以 `reps=1` 与 `reps=4` 重建 agent
（`RL::Random::engine.seed(seed)` + `generator.seed(seed)` + `std::srand(seed)`
必须在**构造 agent 之前**调用），然后统计逐对的成功/失败。

## 7. 附：`LSTM` adding problem 测试的两个独立错误

`test_lstm` Test 9 此前**从未真正跑过**（它先崩溃，见 `optimization_report.md` §9.4），
越界修好后才暴露出下面两个问题：

1. **每个 epoch 只训练 1 个样本。** `lstm.reset()` 会清空 `cacheX`/`cacheE`，
   而 `SGD()` 正是消费它们的地方；原代码把 `SGD()` 放在 200 个序列的循环**之外**，
   于是 199 个序列的梯度被丢掉。
2. **目标不可表示。** `LSTM::feedForward` 对输出套了 `Tanh`，输出 ∈ (−1, 1)；
   而目标是 [0,1] 两个数之和 ∈ [0, 2]（均值 1.0）——**数学上不可能拟合**，
   eval MSE 恒在 0.65 附近，等于平凡"预测均值"解。

修法：逐序列更新 + 目标 ×0.4 缩进 tanh 值域 + 断言"优于平凡均值预测器"。

| | 修复前 | 修复后 |
|---|---|---|
| Test 9 失败率 | **10/20** | **0/20** |
| Eval MSE | ~0.65（≈平凡解） | **0.0014 – 0.0071**（平凡基线 0.0290） |

**附带发现**：`LSTM::SGD/RMSProp/Adam` 是**按权重张量逐个**调用 `Optimize::*` 的，
每个张量各自把梯度归一化到单位 L2 再走 `lr`——即"单位范数梯度下降"，
更新幅度与真实梯度大小无关。这既是第 1 点难以收敛的原因，
也意味着**本库的学习率语义与常规实现不同**（已在 `optimization_report.md` §11 记录）。
